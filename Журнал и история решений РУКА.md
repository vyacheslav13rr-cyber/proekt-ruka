# Журнал и история решений РУКА

## Решения

### Дата неизвестна (внесено ретроспективно) — Роли: переключатель ролей — только демо-функция
- Суть: в продукте переключателя ролей нет — роль закреплена за аккаунтом сотрудника. Переключатель ролей существует только в демо-версии прототипа.
- Причина: в реальном продукте роль сотрудника не меняется им самим, а задаётся при найме/назначении; переключатель в демо нужен только для показа экранов разных ролей на одном билде.

### Дата неизвестна (внесено ретроспективно) — Курсы: номер курса — свойство блюда
- Суть: номер курса при переносе блюда не меняется — курс является свойством самого блюда, а не позиции заказа/стола.
- Причина: перенос блюда между столами/заказами не должен ломать логику подачи по курсам.

### Дата неизвестна (внесено ретроспективно) — Цвета: зелёный и красный больше не зарезервированы под Старт/Стоп
- Суть: зелёный и красный больше не закреплены исключительно за действиями «Старт» и «Стоп» — допускается иное применение этих цветов.
- Причина: прежнее ограничение оказалось избыточным для новых экранов; решение принято напрямую Вячеславом.
- Отменяет: правило из CLAUDE.md («Зелёный по умолчанию используется только для действия "Старт"... красный — только для "Стоп"... Иное применение... только по прямому согласованию с Вячеславом»).

### Дата неизвестна (внесено ретроспективно) — Резервы: ручной ввод, структура под внешний источник
- Суть: резервы заводит вручную менеджер; структура данных резерва проектируется с расчётом на будущее подключение внешнего источника (например, сервиса онлайн-бронирования).
- Причина: чтобы при появлении интеграции с внешним источником резервов не пришлось менять структуру данных.

### Дата неизвестна (внесено ретроспективно) — МН-13: переключатель Плитка/Схема, фильтр по залам, состояния стола
- Суть: на экране МН-13 добавлены переключатель вида «Плитка» / «Схема», фильтр по залам, четыре состояния стола, золотая рамка стола при приближении времени резерва (за 15 минут до), красная рамка — при опоздании гостя.
- Причина: чтобы хостес/менеджер видел состояние столов и приближающиеся или просроченные резервы без захода в каждый стол отдельно.

### Дата неизвестна (внесено ретроспективно) — Новые экраны: МН-24, МН-25, МН-26
- Суть: добавлены экраны МН-24 (карточка резерва), МН-25 (создание резерва), МН-26 (история резервов за смену).
- Причина: разделу резервов (МН-13) нужны отдельные экраны для просмотра, создания и истории резервов.

### Дата неизвестна (внесено ретроспективно) — МН-25: правила полей формы создания резерва
- Суть: дата резерва — только вперёд (прошедшую дату выбрать нельзя); телефон гостя — обязательное поле; ник в Телеграме — опциональное поле.
- Причина: резерв задним числом не имеет смысла; телефон нужен для связи с гостём, Telegram — дополнительный канал связи, доступный не всем гостям.

### Дата неизвестна (внесено ретроспективно) — Настройки резервов: длительность посадки, буфер на уборку, закрытие по счёту
- Суть: добавлены настройки резервов — длительность посадки (время, на которое стол занят под один резерв), буфер времени на уборку стола между резервами, автоматическое закрытие резерва по закрытию счёта.
- Причина: нужны параметры для расчёта доступности столов и для автоматизации статуса резерва.

### Дата неизвестна (внесено ретроспективно) — МН-16: вопрос о закрытии стола при переносе в пустой стол
- Суть: если после переноса заказа/гостей стол остаётся пустым, система спрашивает, закрывать стол или нет.
- Причина: перенос не должен автоматически закрывать стол — решение оставлено на усмотрение сотрудника.

### Дата неизвестна (внесено ретроспективно) — МН-01: два слота под виджеты внизу экрана
- Суть: на экране МН-01 внизу добавлены два слота под виджеты.
- Причина: задел на будущее расширение главного экрана настраиваемыми виджетами.
