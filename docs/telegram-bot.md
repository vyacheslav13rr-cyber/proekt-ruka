# Бот РУКА для тем и расписания в Telegram

Бот принимает от владельца темы для постов и управляет расписанием публикаций в Telegram-канал РУКА. Работает без отдельного сервера: GitHub Actions (сервис автоматических сценариев в самом репозитории) каждые 5 минут опрашивает Telegram на новые сообщения/нажатия кнопок и коммитит изменения прямо в файлы репозитория.

## Настройка (нужно один раз)

В GitHub-репозитории → Settings → Secrets and variables → Actions добавить секреты:

- `TELEGRAM_BOT_TOKEN` — уже используется для публикации, тот же токен бота.
- `TELEGRAM_CHANNEL_ID` — уже используется, ID канала РУКА, куда публикуются посты.
- `TELEGRAM_OWNER_CHAT_ID` — новый секрет: числовой ID твоего личного Telegram-аккаунта (не username). Узнать его можно, например, написав любому боту, который присылает ID в ответ (в Telegram есть публичные боты для этого, найди по названию «userinfobot» или аналогичному через поиск в самом Telegram). Только этот ID бот будет слушать — все остальные сообщения игнорируются.

После добавления секретов написать боту `/start` в личные сообщения — придёт главное меню.

## Меню

Единственный вход в меню — нативная кнопка Telegram «Меню» слева от поля ввода (список команд `/menu`, `/new_topic`, `/new_post`, `/topics`, `/schedule`). Нажал «Меню» → выбрал команду (или просто написал `/menu`) → бот присылает сообщение с кнопками-сеткой (2×2). Отдельной клавиатуры снизу больше нет — раньше пробовали постоянную клавиатуру Telegram, но у неё свой отдельный значок-переключатель, независимый от кнопки «Меню», и получалось два разных входа в одно и то же — это лишнее и путает. Технически объединить их нельзя: у Telegram кнопка «Меню» и постоянная клавиатура — два независимых, никак не связанных между собой механизма.

Сама кнопка-сетка (2×2):

- **📝 Новая тема** — прислать одну строку текста → уходит в раздел «Сырые темы» файла тем. Просто идея, без раскрытого текста поста.
- **🆕 Создать пост** — прислать готовый текст поста (можно в несколько строк) → бот сам создаёт запись в «Разобранных» с новым ID и сразу показывает кнопки «🚀 Опубликовать» / «📅 В расписание».
- **📋 Темы** — посмотреть «Сырые» / «Разобранные» / «Опубликованные». У каждой темы из «Разобранных» на её карточке тоже есть кнопка «🚀 Опубликовать сейчас».
- **📅 Расписание** — полноценный календарь: добавить тему из «Разобранных» на дату/время (московское), посмотреть, изменить дату, удалить. У каждой записи расписания на её карточке тоже есть кнопка «🚀 Опубликовать».

Отдельной кнопки «Опубликовать» в главном меню специально нет — публикация всегда идёт из карточки конкретной темы (в «Темах», в «Расписании» или сразу после «Создать пост»), чтобы нельзя было случайно опубликовать не ту тему.

Расписание — это план и напоминание, а не автопостинг: в назначённое время бот присылает напоминание с кнопкой «Опубликовать», отправка в канал всегда по ручному подтверждению.

Как выглядит диалог с ботом: когда нужен ввод текста (тема, готовый пост, дата), бот не открывает отдельное окошко — он просто пишет в чат просьбу вроде «Пришли текст…», и это обычное сообщение отправляешь как любое другое (написал → нажал «Отправить» у Telegram). Отдельной кнопки «Отправить» внутри бота нет, это и есть отправка.

**Важно про задержку.** Бот не отвечает мгновенно — он не «слушает» чат постоянно, а просыпается раз в 5 минут по расписанию GitHub Actions и забирает все сообщения/нажатия кнопок, накопившиеся с прошлого раза. Поэтому между нажатием кнопки (или отправкой текста) и ответом бота может пройти до 5 минут — это норма, а не зависание.

## Файлы

- `Телеграм/Темы для постинга в телеграм-канал РУКА.md` — единственный файл тем (сырые/разобранные/опубликованные). Формат записи описан прямо в файле.
- `Телеграм/Расписание публикаций РУКА.md` — отдельный файл расписания. Формат описан в файле.
- `.github/scripts/telegram-bot.mjs` — вся логика бота (один скрипт, Node.js, без внешних зависимостей).
- `.github/workflows/telegram-bot.yml` — расписание запуска (каждые 5 минут) + ручной запуск.
- `.github/state/telegram-bot-state.json` — служебное состояние между запусками (смещение опроса Telegram, недописанные диалоги вроде «жду дату для расписания»). Редактировать вручную не нужно.

## Как разбирать сырую тему в готовый пост

Бот сам это не делает — текст поста пишется вручную (или вместе с Claude) прямо в файле тем, в разделе «Разобранные», по формату из этого же файла (блок `<!-- topic id=T-000N status=ready -->` … `<!-- /topic -->`, картинка — последней строкой `Картинка: путь`). После этого тема появится в кнопках «Расписание» и «Опубликовать» у бота.

## Ручная публикация без бота

`.github/workflows/telegram-post.yml` остаётся отдельно — запуск вручную из вкладки Actions с текстом и (опционально) картинкой, в обход бота и файла тем.
